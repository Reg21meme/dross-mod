# Blightwood candidates (tools/blight)

Makes the frozen candidate models for Blightwood, the Plague Necromancer's biome (the user, November 7, 2026: "15
different bosses you can choose from, of different sizes and shapes, maybe stick to something smaller, then 4-5 base
mobs we can add to the Blightwood ... no animations or anything yet, just designs ... make them different boss ideas
each"). Two sets (`SETS` in `build.py`), one gallery in the game, `/dross showcase boss_designs blightwood`:

- **`bosses`** (files `blightdesigns/bNN_*.py`, labels "1"-"15"): fifteen possible bosses for the Plague Necromancer's
  two open servant places (the Rat King is the first; the boss-site planner keeps Blightwood slots 1 and 2 free,
  CLAUDE.md step 12), each a different idea and body shape, from 1.6 to 7 blocks tall.
- **`mobs`** (files `blightdesigns/mNN_*.py`, labels "M1"-"M5"): five possible regular Blightwood mobs to live beside its
  rats and witches.

Each design module's `BLURB` gives its idea and how its fight would start; it's in the Java list too, so the game shows
it (hover over a [go] button, or right-click a model).

Everything is generated by Python, never drawn by hand, the same way as the fire and Rimefall candidates, whose kits this
reuses (`tools/rimefall/rimekit`: shapes, per-face UVs, the floating-piece and z-fighting checks, the previews;
`tools/fire/firekit`: its painters and shape helpers); see `BOSS_GUIDE.md`. The Plague colours (poison green, decaying
reds, bone beige), never the Dross blue: `blightkit/bmats.py` (palettes, and `spotted`, a painter of mottled skin or
caps with round spots placed by world position, glowing if asked: Blightcap caps, pustules, mould, rust).
`blightkit/bparts.py`: `mushroom` (a stem, a domed cap and its gills along any direction), `shelf` (bracket fungus),
`tendril`, `quad_leg`.

## Running it

From the project folder:

```
python tools/blight/build.py                    # everything (about a minute): files, previews, the Java list
python tools/blight/build.py --only 1 5 M2      # only these designs' files and previews (no Java list)
python tools/blight/build.py --quick <dir> 1 M2 # quick sheets of these designs into <dir> (nothing in the project)
python tools/blight/build.py --board <dir> 1 M2 # one picture per design: front, three-quarter, behind, at night
python tools/blight/build.py --previews-only    # previews only; the game files are left alone
python tools/blight/zcheck.py 4                 # lists any face pairs that would still flicker
```

Needs Python 3 with numpy and Pillow.

## What it writes

| File | What |
|---|---|
| `assets/dross/geo/entity/blight/<id>.geo.json` | the model (per-face UVs) |
| `assets/dross/textures/entity/blight/<id>.png` | the solid parts (what you can see through is a hole here) |
| `.../<id>_glow.png` | what glows, drawn full-bright (eyes, pustules, ooze, the puppet strings) |
| `.../<id>_clear.png`, `_clearglow.png` | the see-through parts (the Sump's ooze, the fly's wings, the slime trail, bottles) and what glows on them |
| `assets/dross/animations/entity/blight/candidate.animation.json` | empty (nothing moves) |
| `src/main/java/com/reg21meme/dross/boss/blight/BlightDesigns.java` | the generated list the game reads |
| `boss-previews/blightwood/servants/` | the bosses: a sheet each, `originals.png`, `lineup.png`, `index.html` |
| `boss-previews/blightwood/mobs/` | the same for the mobs |

The models are showcase-only: `build.gradle`'s `jar` task leaves `entity/blight/` out of the released jar, and
`boss/ShowcaseOnly` then doesn't offer the gallery.

## Changing a design

Edit its module in `blightdesigns/` (Bedrock units, 16 a block, y up from the feet, the front facing -z, its own left
+x), then run `build.py --board <scratch dir> <label>` to look, and `build.py` to write it. A sign line holds 15
characters (`NAME`, `MOOD`): the build stops if one is longer. Ids are lower case without underscores.
