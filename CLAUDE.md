# Dross — Minecraft Forge mod

## Project summary
- Minecraft **1.20.1**, Forge **47.4.10** (recommended build), Java **17** (Temurin), Gradle 8.8 via the wrapper.
- Mod ID `dross`, display name `Dross`, base package `com.reg21meme.dross`, main class `Dross.java`.
- Mappings: `official` (Mojang names). Mod metadata: `src/main/resources/META-INF/mods.toml`, filled from `gradle.properties`.
- **GeckoLib 4.8.4** (Forge 1.20.1, `geckolib_version` in `gradle.properties`) draws and animates the boss models. It's a required dependency: players need it installed too (`mods.toml` lists it). `build.gradle` remaps its mixin refmap in the dev runs (`mixin.env.*` properties) and turns off its example mobs (`geckolib.disable_examples`).
- GitHub: https://github.com/Reg21meme/dross-mod (branch `main`).
- The user is a **beginner**. Explain changes in plain language. **Never commit or push unless the user asks.**

## Commands (Windows, run from the project folder)
- Build: `.\gradlew.bat build --console=plain` (output jar: `build/libs/dross-<version>.jar`)
- Run the game: `.\gradlew.bat runClient --console=plain`. This blocks until the game window closes. The user often closes the game themselves, which is normal.
- Game logs: `run/logs/latest.log` (and `debug.log`). Crash reports: `run/crash-reports/`.
- If a first-time setup fails with `NoSuchFileException` under `.gradle/caches/forge_gradle/maven_downloader`, that is a flaky parallel download. Re-run the same command.
- To test commands in-game, create the world with **Allow Cheats: ON**.

## Rules for every agent
1. Forge 1.20.1 / Java 17 APIs only. Use `DeferredRegister` for all registrations. Watch out for newer-version APIs that don't exist here: no `ResourceLocation.fromNamespaceAndPath` (use `new ResourceLocation(Dross.MODID, "path")`), no data components, no NeoForge classes, no `neoforge.mods.toml`.
2. **Shared files: only ADD your own entries.** Never rewrite, reorder, rename or remove another area's entries. Shared files are:
   - `Dross.java`: add one line per thing you need registered on the mod event bus (for example `ModBlocks.BLOCKS.register(modEventBus);`). If `modEventBus` doesn't exist yet, add `IEventBus modEventBus = context.getModEventBus();` once at the top of the constructor.
   - Registry classes in `com.reg21meme.dross.registry`: `ModBlocks`, `ModBlockEntities`, `ModItems`, `ModEntities`, `ModParticles`, `ModCreativeTabs`, `ModEnchantments`, `ModLootModifiers` (create one if it doesn't exist yet, holding only the `DeferredRegister` and your entries).
   - `ModCreativeTabs`: the Dross tab is grouped by kind, in this order (the user's request): 1. blocks, 2. quest items, 3. trophies, 4. spawn eggs, 5. weapons and tools, 6. enchanted books (Necromancy, then Deathforged). Add a new item at the end of its group; the comment in the file lists the groups.
   - `src/main/resources/assets/dross/lang/en_us.json`: add keys only.
   - `DrossColors.java` (`com.reg21meme.dross.DrossColors`): add constants in your own area's section, and change only your own area's values.
3. **Stay in your own area** (see the table below). If you need something from another area, don't build it. Report it as "Needs from <area>: ...".
4. Prefer your own `@Mod.EventBusSubscriber` classes inside your package over adding event code to `Dross.java`.
5. After changes, run `.\gradlew.bat build --console=plain` and fix any errors **in your own area**. If the error is in another area's code, report it instead.
6. Finish with a short, beginner-friendly explanation: what you added, which files, and how to test it in-game.
7. Don't commit.
8. **Colors come from `DrossColors`.** Never hard-code a color in feature code (particles, glows, text styles, spawn eggs). If you need a new color, add a labeled constant in your area's section of `DrossColors`. Some older code still has hard-coded colors; move it onto `DrossColors` when you next change that code.
9. **`/dross` command names** say what kind of thing a command is about and which one, so they stay clear as more bosses and places arrive (world-builder adds them to `command/DrossCommand`; if you need one, report it as "Needs from world site"):
   - `goto <place>`: teleports (`goto cathedral`, `goto hub`, `goto trader`).
   - `showcase <kind> [<boss>]`: test showcases (`showcase trader_huts`, `showcase trader_skins`, `showcase portal_shrines`, `showcase boss_designs colossus`, `showcase trophies colossus`). A new boss adds one literal under each kind it has.
   - `boss <action> <boss>`: boss test tools (`boss summon colossus`, `boss arena colossus`).
   - `trader <action>`: the trader (`trader sendhome`).
   - `quest <action>`: quest progress (`quest status`, `quest reset`, `quest complete`).

## The plan
The full design, including the **early-game quest** from `EARLY_GAME_PLAN.md`, which replaces the old test quest (nether star for a compass, netherite ingot lights the bare frame at 0,0, arrival next to an auto-built return portal).
- **[built]** means it's in the game now.
- **[to build]** means it's planned but not in the game yet. Nothing is marked [to build] right now: the Cinder Colossus fight (step 8) is built (not yet tested in-game); new work goes here first.

The Dross is a **mid-to-late game** place: players reach it after proving they survived dangerous places, not after beating every boss. It should work well alongside other mods. The only way in is the castle portal and the only way out is the hub, so the Dross stays dangerous.

### The look: electric blue [built]
- The Dross's color is **electric blue** (deep cobalt / electric blue, clearly different from vanilla's cyan soul fire). It replaced the old orange everywhere: portal texture, portal particles, screen swirl, frame, the trader's teleport particles and glow, the spawn egg spots, the risen undead's puffs and wisps, and the arrival title.
- Every color is a labeled constant in `DrossColors`. The palette is main `0x2E6BFF`, deep cobalt `0x0B2A9E` and highlight `0x7FA8FF`, kept in a shared "Palette" section of `DrossColors`. Each area points its own constants at it.
- A glow given through a scoreboard team can only use a chat color (`ChatFormatting.BLUE` is the closest); nothing uses one now. The trader's glow uses the exact RGB.
- **Not recolored:** the Admin Sword texture (parked for removal) and the soul tooltip text (stays gold).

### Steps
1. **Dross dimension** (`dross:dross`) [built]: superflat, permanent night (`fixed_time` 18000), normal hostile mob spawn rates.
   - Zombies spawn in full netherite armor + netherite sword. Skeletons spawn in full netherite armor and keep their bows. Nothing is enchanted (including the bow). None of this gear drops on death. Risen undead (step 6) are skipped by this rule: their gear comes only from Deathforged.
   - Slimes, creepers and spiders are removed from the spawn list.
   - Players see the dimension named **"The Dross"** (lang key `dimension.dross.dross`).
   - Terrain is defined in data JSON with its own biome so it can be upgraded later without rewriting Java.
   - [built] The hub at Dross 0,0 is a safe zone (step 5).

2. **Dross portal**
   - **Frame** [built]: a custom block, `dross:dross_portal_frame`, which **can't be crafted or mined** (no recipe, no drops, unbreakable, blast-proof). For testing, it has a block item that is only available in the creative **"Dross"** tab (or `/give`); it still has no recipe, drops nothing and can't be broken in survival. Flint and steel can't light it, and normal obsidian frames stay normal purple nether portals.
   - **Frame look** [built]: an **original** texture (dark stone with electric blue cracks), no longer based on Mojang's obsidian.
   - **"The Dross is leaking out"** [built]: frame blocks give off drifting electric blue particles and a low ambient sound. This applies to every frame, including the unlit castle frame.
   - **Lighting** [built]: throwing the **Rift Key** (step 7) into the empty middle of a valid frame (along X or Z) **uses up the key** and lights the portal.
     - If that frame is already lit, the key isn't used: it pops back out, with a portal cooldown so it doesn't drift into the Dross.
     - A netherite ingot no longer lights anything.
   - **No portals inside the Dross** [built]: the Rift Key does nothing there, and lighting a nether portal (flint and steel or fire on obsidian) is blocked there. Otherwise a nether portal would be a second way out.
   - **Portal look** [built]: Minecraft's nether portal texture copied and recolored **electric blue** (still a recolor, see Parked), blue particles, and a blue in-portal screen swirl.
   - **Stays open**: once lit, the castle portal stays open permanently, for everyone.
   - **Travel** [built]:
     - Every Dross portal outside the Dross leads to the **hub at Dross 0,0** (step 5).
     - The hub's exit portal always leads to the **castle portal** (`PortalSite`), wherever the player came in.
     - No more auto-built return portals, and no saved return-portal lookup.
     - All entities can travel. Never place an entity inside blocks or above a void drop.

3. **The castle (portal site)**
   - **The castle** [built]:
     - Placed once per world, at the site location, on flattened ground (reuse the existing site-placement logic). The frame is unlit and fully unbreakable.
     - If `data/dross/structures/portal_castle.nbt` exists, that template is placed. The user builds it in creative and saves it with a structure block as `dross:portal_castle`.
     - Otherwise the **Fallen Cathedral** [built] (shrine design No. 1, the user's pick; `world/PortalCathedral`, `ShrineDesign.buildFitted`, `world/shrine/GroundFit`, `world/shrine/TreeFelling`): its 3x5 frame opening (along X) sits on the site column (see **Location**), front facing south. Its 61x87 footprint is fitted gently into the (already nearly flat) ground:
       - the footprint is levelled at the median natural height by cutting or filling a few blocks; small dips and caves just under the ground are filled (never deeper than 8 / 16 blocks); no big foundations;
       - **staircase blend** [built]: around the footprint, a column d blocks out is never more than d above or below the build level, so the ground steps at most 1 block at a time back to the natural terrain (no cliffs or walls of dirt); one column is never changed by more than 8 blocks (`MAX_RING_CHANGE`); new ground keeps each column's own top layer (grass, podzol, sand over sandstone, snow);
       - **trees** [built]: only trees that touch the footprint or a reshaped column are removed, and always whole (logs, leaves, vines, bee nests, snow on them); leaves no remaining log holds up go too, other trees are left alone. Huge mushrooms and ice spikes follow the same rule.
     - Only if the cathedral can't be built (template missing, or its frame fails the check; an ERROR is logged), the small placeholder ruined shrine (`PortalShrine`, vanilla stone bricks, 4×5 frame along X) is built instead.
     - Old worlds keep what they have: the bare frame (worlds from before the castle, treated as an X-axis frame) or the small placeholder shrine.
     - The template must contain exactly **one** complete Dross frame with an empty opening (either direction). The code finds it and stores its bottom corner **and axis**.
     - Structure blocks save at most 48×48×48 in 1.20.1, so a bigger castle needs several pieces.
   - **Location** [built] (`world/SiteRules`, `SiteSearch`, `SiteCheck`, `PortalSitePlacer`, `SiteVillages`; all rules are labeled constants in `SiteRules`): chosen once when a new world starts and saved in `PortalSiteData`; old worlds keep their site.
     - A random spot **3,000–10,000 blocks from world spawn** in an allowed biome: plains, sunflower plains, desert, taiga, old growth pine/spruce taiga, snowy taiga, forest, flower forest, birch forest, old growth birch forest, dark forest, snowy plains, ice spikes. Never ocean, river (frozen ones too), beach or swamp, and no water under or within 4 blocks of the footprint.
     - The natural ground under the footprint must vary by **5 blocks or less** (`MAX_VARIATION`; a few small dips, up to 1% of the columns (`SMALL_DIP_SHARE`), don't count). No village (possible village starts, then the real village bounding boxes) within the margin around the blending ring.
     - Background search with the world generator's own height and biome maths (no chunks generated), then the best spot is checked in the real generated world (chunks loaded with tickets); a failed spot is remembered and the next tried. If nothing passes, the rules relax step by step with a WARN (6 → 8 → any dry-land biome at 8 → a last-resort steep level at 12), so a world always gets a site. Placing takes about a minute after a new world starts.
     - Before it's built, the `PortalSite` getters report the planned spot (a guess 3,000 blocks east of spawn in the first moments); `PortalSiteBuilder.ensurePlaced` (used by leaving the Dross) builds it right away if needed.
     - **Location in chat** [built] (`world/SiteAnnouncer`, lang key `dross.site.location`): when the site is placed (any build path, sent from `PortalSitePlacer.Job.placed`), everyone online gets "Dross portal site is at X, Y, Z" (`getOpeningCenter`), and each player gets it again whenever they join a world where it's placed (old worlds' bare frame or shrine count as placed). Plain text.
   - **`PortalSite` API is axis-aware** [built]: `getFramePos` (bottom corner), `getFrameAxis`, `getOpeningCenter` (middle block of the opening's bottom row), `getOpeningWidth` and `getOpeningHeight`. The compass, `/dross goto cathedral` and the hub's exit portal use them.
   - **Leaking** [built]: once, when the castle is placed, within about 16 blocks:
     - flowers and grass become dead bushes or are removed,
     - some grass blocks become coarse dirt,
     - stone bricks become cracked stone bricks.

     The particles and sound come from the frame blocks (step 2).
   - **`/dross goto cathedral`**: teleports the player in front of the frame, facing it (axis-aware). Before the site is placed it builds nothing and fails with "The Dross portal site hasn't been placed in this world yet." (like `/dross goto trader`). `world/PortalSiteGameTest` checks the join message and this command headlessly.
   - **Grander shrine candidates** [built, showcase only]: 10 big ruined landmarks that could replace the small placeholder shrine. Each has one unlit 5x7 frame (opening 3x5) at its heart and the Dross leaking out around it: glowing blue cracks (blue glass over sea lanterns, lapis), dead ground and plants, broken frame shards that leak dust.
     - 1 Fallen Cathedral, 2 Shattered Spire, 3 Sunken Temple, 4 The Colosseum, 5 Overgrown Keep, 6 Fallen Colossus, 7 Monolith Ring, 8 Dead World Tree, 9 Riven Ziggurat, 10 Old Observatory. 61-77 blocks wide, 65-87 deep, 29-65 tall.
     - Each is a structure template (`data/dross/structures/shrine/<id>.nbt`) made by `tools/shrines/` (Python; see its README). Its front faces south and its ground is layer 2, two layers reach underground. Change a design in Python, then re-run the generator and `gen_java.py`.
     - `/dross showcase portal_shrines` builds all 10 in a row, one at a time, each with a sign; clicking a chat line teleports you to it.
     - **The user picked No. 1, the Fallen Cathedral, for the Overworld portal site (above) and No. 2, the Shattered Spire, for the hub in the Dross (step 5).** The other eight stay in the showcase.

4. **Dross trader** (villager) [built]: spawns once per world, in his own **hut at the edge of the closest village (to world spawn) that has room for it**. He wears skin 2, **The Archivist** [built] (see "Skins" below). He can be hurt and knocked back but **can never die**, because he only ever spawns once: at half health or less he teleports home and fully heals.
   - **Which village and when** (`TraderSpawner`, `VillageSearchPlan`): at world start he lists every possible village chunk within 5,000 blocks of spawn. He takes the **5 nearest villages within 1,000 blocks** (a 2,000 x 2,000 square), generates all 5 at once in the background (chunk tickets, 180 s timeout), and builds at the closest one with a good spot. If none fit, the next 5 farther out, the square growing by 1,000 blocks at a time up to 5,000. The log says which village was picked and why (one line per village checked). He spawns once the hut is built, which can take a while after the world opens.
   - **Emergency:** only if no village within 5,000 blocks has a spot (for example Generate Structures is off), the chapel is built on the nearest flat spot near world spawn (any biome, door facing spawn, no path) with a WARN in the log. `TraderSpawnData.isInVillage()` is false then.
   - **Hut: the Rift Chapel** (`villager/hut/RiftChapel`, picked with `/dross showcase trader_huts`; `TraderHut.DESIGN`), 9 wide x 13 deep x 18 tall. A small stone chapel: deepslate base, stone brick walls with lapis blocks here and there, buttresses, tall blue windows, a steep deepslate-tile roof, a blue rose window over the dark oak door, an open belfry with a soul lantern, and a spire topped with an end rod and a copper lightning rod. Inside: pews, blue banners, soul lanterns on chains, and behind the altar a broken piece of a real Dross portal frame (unbreakable, leaks blue dust and hums; it's incomplete, so it can't be lit). He stands in the aisle.
     - It sits in the village, right next to its houses (about 3 blocks from the nearest village piece), never overlapping or touching any house, street, decoration or path block (2-block margin around every village piece). Its door faces the nearest street, and it prefers flat ground. Small bumps are levelled: the floor may sit up to 3 blocks below the highest ground (bumps cut, grass put back) and up to 3 above the lowest (dips filled), choosing the least earthwork; the doorstep stays within 1 block of the floor.
     - A **3-wide path** in the village's own path material (dirt path; smooth sandstone in desert villages) follows the ground from its door to the nearest street. It only replaces natural ground.
     - The lightning rod draws natural lightning within 128 blocks to the spire (harmless, and it shields the village).
     - Old worlds keep their 5x5 netherite hut: he only ever spawns once per world.
   - **Behavior:** he wanders within 50 blocks of his hut (X and Z) and opens his door. If he's more than 50 blocks out, falls more than 4 blocks, or is more than 3 blocks below the surface (not counting his hut, whose footprint is saved on him as `HutBox`, or village buildings), he teleports to his spot in the hut (the chapel's aisle) with the enderman sound and enderman-style particles (the portal's electric blue particles). If he's riding a boat, minecart or anything else, he gets off first (the vehicle stays where it was) and anything riding him is thrown off. He can't use portals.
   - **Glow (finding aid):** while any player is within his 50-block area, he glows electric blue with an outline visible through walls.
   - **Quest and dialogue:** see step 7.
   - **Shop:**
     - The old test trades (nether star → compass, the Admin Sword, Necromancy I–IV) are gone.
     - After a player completes the quest he sells **Necromancy (its lowest level)** for 32 emeralds + book and **Deathforged I** for 24 emeralds + book. Unlimited uses, no restock, no XP.
     - The offers are the same for everyone, but the trading screen only opens for players who completed the quest (received the Rift Key).
     - His key-forging line ends by pointing to the shop: "...be careful what you let out. I've got some books that can help you in there." (`dross.trader.dialogue.key_forged`).
     - **Dross Guide Book**: for players who have the "Enter the Dross" advancement, he also sells the Dross Guide Book for 3 books (no emeralds; a labeled constant). Unlimited uses, no restock, no XP. Players without that advancement don't see this offer.
     - Existing traders in old worlds get their old offers replaced once when they load (`SHOP_VERSION` in `DrossTrader`; bump it whenever the base shop changes).
   - **Spawn egg:** "Dross Trader Spawn Egg" in the creative Dross tab (electric blue spots). An egg trader treats the spot he was spawned at as his home, with the same 50-block area, glow and teleport-home rules.
   - **Test tools:** `/dross goto trader` teleports you to him (even if his area isn't loaded) and `/dross trader sendhome` sends him home. `/dross showcase trader_huts` builds all 10 candidate hut designs in a row in front of you, each with a numbered sign. His entity ID is `dross:dross_trader`; `@e` selectors only find him while his area is loaded.
   - The old test-only join message (`TestingJoinMessage`, "[Dross test] ...") is removed.
   - **Location in chat** [built] (`villager/TraderAnnouncer`, lang key `dross.trader.location`): when the real trader spawns (village chapel or emergency chapel, sent from `TraderSpawner.buildAndSpawn`), everyone online gets "Dross trader's hut is at X, Y, Z" (`TraderSpawnData.getPos()`), and each player gets it again whenever they join a world where he has spawned (old netherite huts included). Spawn-egg and showcase traders never send it. Plain text; matches the site's message (step 3). `villager/TraderAnnouncerGameTest` checks it headlessly.
   - **Skins** [built]: 10 original electric blue skins on the vanilla villager model (`TraderSkins`): 1 Hooded Watcher, 2 The Archivist, 3 Ragged Seeker, 4 Rift Regent, 5 Shard Hermit, 6 Wayfarer, 7 Stargazer, 8 Blind Oracle, 9 Rift Warden, 10 Alchemist.
     - **The Archivist** [built]: **the user picked skin 2, The Archivist, for the quest trader** (`TraderSkins.QUEST_TRADER`). Every trader has a skin number (synced, saved as `Skin`); 0, the default, means the quest trader's look (`TraderSkins.lookFor`), so the real trader and spawn-egg traders wear it in old and new worlds alike. 6. **Necromancy and Deathforged** (enchantments, `com.reg21meme.dross.enchant`) [built]. All tuning numbers are labeled constants at the top of their files.

     |---|---|---|---|---|
     | I | 15% | 1 | 25 | zombie, skeleton |
     | II | 20% | 2 | 50 | zombie, skeleton |
     | III | 25% | 4 | 100 | + husk, stray, drowned |
     | IV | 30% | 6 | 250 | + chicken jockey, spider jockey, skeleton horseman |
     | V (admin, testing only) | 100% | 10 | infinite | same as IV |

     Old items were remapped once when this five-level version arrived (old I→II, II→III, III→IV, IV→V; `enchant/NecromancyScheme`, a marker tag on every new-scheme item).

   - **Hits:** only a melee hit with the sword in the main hand on the **main target** of a swing (sweep hits never roll). Hitting a player, the Dross trader or your own risen undead never raises any.
   - **How many:** if none of yours are alive, a success raises the full max; otherwise half the max, rounded up (I: 1, II: 1, III: 2, IV: 3, V: 5), never over the max ("alive" counts per player). Each costs 1 soul; a jockey/horseman takes 1 slot but costs 2 souls (with only 1 soul left, a normal undead rises instead). Not enough souls: raise as many as the souls allow. Each one's type is random from the types the level unlocks.
   - **Souls:** killing any zombie, skeleton or variant (anything that is a kind of zombie or skeleton) with the sword stores 1 soul, up to the level's capacity; risen undead give none. An electric blue wisp flies from the mob into the player's hand. Souls are stored on the sword itself (item tag), so each sword has its own count and it moves with the sword. Tooltip: "Souls: X / Y" ("Souls: ∞" at V; V never spends souls), in gold.
   - **Risen undead** (real vanilla mobs, owner stored in their persistent data) fight as a **pack**. A free risen undead picks, in order: a mob attacking or targeting its owner (within 16 blocks), the owner's target (hit within the last 5 s), a mob that hurt it, then any fight one of the owner's other risen undead within 16 blocks is in; otherwise it follows the owner. One that's already fighting keeps its target until it dies or becomes invalid; when a fight ends it helps allies still fighting before following. A target that is dead, dying or removed is dropped right away, even the mob whose hit raised them dying on that same hit, and any walk toward it stops at the same moment, so skeletons lower their bows instead of walking to the empty spot (`RisenTargetGoal` sets and clears every target itself and ends the fight with `endFight`; `RisenTargetGameTest` checks both headlessly). They never target or hurt players (arrows included), the Dross trader, villagers, wandering traders, or their owner's other risen undead (even if the owner hits a villager or wandering trader). The owner's own hits (sweep included) never damage their risen undead. Whenever a risen undead damages a mob (arrows included), that mob switches its target to the risen undead that hit it, including zombies, skeletons and their variants, which normally ignore other undead. Risen drowned always fight on land, day or night. On Peaceful, Necromancy does nothing and no souls are spent. They crumble in a puff of electric blue particles after 60 seconds, or early if the owner logs out, dies or changes dimension, or if their chunk is reloaded from a save. No drops, no XP, no item pickup, no portals, no conversions (zombie→drowned, skeleton→stray). Vanilla burning rules (helmets protect, husks don't burn).
   - **Deathforged** (swords only, I–X; does nothing without Necromancy on the same sword): "Your risen undead come armored. Higher levels forge stronger gear." Armor (all types) / sword (zombie types only): I leather / none, II leather / wooden, III gold / gold, IV chainmail / stone, V iron / stone, VI iron / iron, VII diamond / iron, VIII diamond / diamond, IX netherite / netherite, X netherite / netherite + Strength I and Speed I for their whole life (particles hidden, no glow). Nothing is ever enchanted and nothing drops. Skeleton types always get a plain, unenchanted bow; without Deathforged: no armor. Mounts get no gear. The table is `GEAR_BY_LEVEL` in `DeathforgedEnchantment`; `DeathforgedGearGameTest` checks every level headlessly. (Until October 2026, VIII–IX enchanted the gear and X glowed through a shared `dross_risen_glow` team; that team is deleted at server start in old worlds.)
   - **Rules for both:** treasure only (never from the enchanting table, loot chests, fishing or normal librarians). Books work at an anvil. **Deathforged I–V** combine normally with vanilla XP costs (I+I→II … IV+IV→V), capped at V (V+V gives nothing); if both items carry Deathforged and either is VI–X, no result (a single VI–X book still goes onto a sword with no Deathforged). **Necromancy** never levels up at an anvil: two same-level Necromancy books (or a book onto a sword with that level) give no result, but two swords may combine; the result keeps the (higher) Necromancy level, only Deathforged combines (I–V rules above), and the souls from both swords add up, capped at the result's capacity. A combine that changes nothing (no enchantment gain, repair or rename) gives no result. Necromancy can't be combined with Smite. Rarity keeps Deathforged X under the anvil's "Too Expensive!" limit.
   - **Getting them:**

   - **Advancement "Rise!"** (`dross:rise`): "Raise the undead with Necromancy.", challenge frame (purple), zombie head icon, granted the first time a player raises undead, through Quest's grant helper. It's in the Dross tab (step 7), parent "Enter the Dross".
