# Dross — Minecraft Forge mod

## Project summary
- Minecraft **1.20.1**, Forge **47.4.10** (recommended build), Java **17** (Temurin), Gradle 8.8 via the wrapper.
- Mod ID `dross`, display name `Dross`, base package `com.reg21meme.dross`, main class `Dross.java`.
- Mappings: `official` (Mojang names). Mod metadata: `src/main/resources/META-INF/mods.toml`, filled from `gradle.properties`.
- **GeckoLib 4.8.4** (Forge 1.20.1, `geckolib_version` in `gradle.properties`) draws and animates the boss models. It's a required dependency: players need it installed too (`mods.toml` lists it). `build.gradle` remaps its mixin refmap in the dev runs (`mixin.env.*` properties) and turns off its example mobs (`geckolib.disable_examples`).
- GitHub: https://github.com/Reg21meme/dross-mod (branch `main`).
- The user is a **beginner**. Explain changes in plain language. **Never commit or push unless the user asks.**

## Commands (Windows, run from the project folder)
- Build: `.\gradlew.bat build --console=plain` (output jar: `build/libs/dross-<version>.jar`)
- Run the game: `.\gradlew.bat runClient --console=plain`. This blocks until the game window closes. The user often closes the game themselves, which is normal.
- Game logs: `run/logs/latest.log` (and `debug.log`). Crash reports: `run/crash-reports/`.
- If a first-time setup fails with `NoSuchFileException` under `.gradle/caches/forge_gradle/maven_downloader`, that is a flaky parallel download. Re-run the same command.
- To test commands in-game, create the world with **Allow Cheats: ON**.
- Headless checks: `.\gradlew.bat runGameTestServer --console=plain` runs every GameTest without a game window. Add `-PgameTestWorld=<new folder>` for a brand-new world (the folder under `run/` must not exist yet; otherwise it reuses `run/world`). Confirm the `All N required tests passed :)` line: a datapack load failure can still exit 0.
- GameTests live in `src/main/java` (files named `*GameTest.java`) but **stay out of the mod jar**: `build.gradle`'s `jar` task excludes them and the test-only helpers `dimension/TerrainProbe`, `dimension/TerrainSurvey` and `enchant/RisenTestWait`. A new test-only helper class goes on that list, and game code must never use a test class (the jar would break).

## Rules for every agent
1. Forge 1.20.1 / Java 17 APIs only. Use `DeferredRegister` for all registrations. Watch out for newer-version APIs that don't exist here: no `ResourceLocation.fromNamespaceAndPath` (use `new ResourceLocation(Dross.MODID, "path")`), no data components, no NeoForge classes, no `neoforge.mods.toml`.
2. **Shared files: only ADD your own entries.** Never rewrite, reorder, rename or remove another area's entries. Shared files are:
   - `Dross.java`: add one line per thing you need registered on the mod event bus (for example `ModBlocks.BLOCKS.register(modEventBus);`). If `modEventBus` doesn't exist yet, add `IEventBus modEventBus = context.getModEventBus();` once at the top of the constructor.
   - Registry classes in `com.reg21meme.dross.registry`: `ModBlocks`, `ModBlockEntities`, `ModItems`, `ModEntities`, `ModParticles`, `ModCreativeTabs`, `ModEnchantments`, `ModLootModifiers`, `ModSounds`, `ModTreeDecorators`, `ModDensityFunctions`, `ModFeatures`, `ModPlacementModifiers`, `ModEffects`, `ModStructures` (create one if it doesn't exist yet, holding only the `DeferredRegister` and your entries).
   - `ModCreativeTabs`: the Dross tab is grouped by kind, in this order (the user's request): 1. blocks, 2. quest items, 3. trophies, 4. spawn eggs, 5. weapons and tools, 6. enchanted books (Necromancy, then Deathforged), 7. materials (Raw Moonsilver, Moonsilver Ingot, Stormite Shard). Add a new item at the end of its group; the comment in the file lists the groups.
   - `src/main/resources/assets/dross/lang/en_us.json`: add keys only.
   - `DrossColors.java` (`com.reg21meme.dross.DrossColors`): add constants in your own area's section, and change only your own area's values.
3. **Stay in your own area** (see the table below). If you need something from another area, don't build it. Report it as "Needs from <area>: ...".
4. Prefer your own `@Mod.EventBusSubscriber` classes inside your package over adding event code to `Dross.java`.
5. After changes, run `.\gradlew.bat build --console=plain` and fix any errors **in your own area**. If the error is in another area's code, report it instead.
6. Finish with a short, beginner-friendly explanation: what you added, which files, and how to test it in-game.
7. Don't commit.
8. **Colors come from `DrossColors`.** Never hard-code a color in feature code (particles, glows, text styles, spawn eggs). If you need a new color, add a labeled constant in your area's section of `DrossColors`. Some older code still has hard-coded colors; move it onto `DrossColors` when you next change that code.
9. **`/dross` command names** say what kind of thing a command is about and which one, so they stay clear as more bosses and places arrive (world-builder adds them to `command/DrossCommand`; if you need one, report it as "Needs from world site"):
   - `goto <place>`: teleports (`goto cathedral`, `goto hub`, `goto trader`, `goto sewer`). A kind of place names its kind first: `goto biome <name>` (one per Dross biome) and `goto lair <boss>` (`goto lair colossus`, `goto lair ratking`).
   - `showcase <kind> [<boss>]`: test showcases (`showcase boss_designs colossus`, `showcase boss_designs ratking`, `showcase rats`, `showcase boss_sounds ratking`, `showcase trophies colossus`, `showcase trophies ratking`). A new boss adds one literal under each kind it has; a boss's minions get their own kind (`showcase rats`).
   - `boss <action> <boss>`: boss test tools (`boss summon colossus`, `boss arena colossus`, `boss summon ratking`, `boss arena ratking`).
   - `trader <action>`: the trader (`trader sendhome`).
   - `quest <action>`: quest progress (`quest status`, `quest reset`, `quest complete`).
10. **Making a new boss (or mini-boss): follow [`BOSS_GUIDE.md`](BOSS_GUIDE.md)** step by step: questions up front, a separate linked copy if other sessions are working, a Python generator in `tools/<boss>/` reusing the golem kit, checking every preview yourself, the Java and showcase commands, GameTests, the in-game photo check (`tools/photo_booth/`), the hand-over, and the docs after the user's pick. **Every boss's previews go in its own folder, `boss-previews/<boss>/`** (minions in a subfolder); nothing goes straight into `boss-previews/`.

## The plan
The full design, including the **early-game quest** from `EARLY_GAME_PLAN.md`, which replaces the old test quest (nether star for a compass, netherite ingot lights the bare frame at 0,0, arrival next to an auto-built return portal).
- **[built]** means it's in the game now.
- **[to build]** means it's planned but not in the game yet. Nothing is marked [to build] right now: the Cinder Colossus fight (step 8), the Rat King (step 9: Gnawrick 1C, his rats, sounds, fight and trophies) and the Rage Wand (step 10) are built and the user has tested them in-game; new work goes here first.

The Dross is a **mid-to-late game** place: players reach it after proving they survived dangerous places, not after beating every boss. It should work well alongside other mods. The only way in is the castle portal and the only way out is the hub, so the Dross stays dangerous.

### The look: electric blue [built]
- The Dross's color is **electric blue** (deep cobalt / electric blue, clearly different from vanilla's cyan soul fire). It replaced the old orange everywhere: portal texture, portal particles, screen swirl, frame, the trader's teleport particles and glow, the spawn egg spots, the risen undead's puffs and wisps, and the arrival title.
- Every color is a labeled constant in `DrossColors`. The palette is main `0x2E6BFF`, deep cobalt `0x0B2A9E` and highlight `0x7FA8FF`, kept in a shared "Palette" section of `DrossColors`. Each area points its own constants at it.
- A glow given through a scoreboard team can only use a chat color (`ChatFormatting.BLUE` is the closest); nothing uses one now. The trader's glow uses the exact RGB.
- **Not recolored:** the Admin Sword texture (parked for removal) and the soul tooltip text (stays gold).

### Steps
1. **Dross dimension** (`dross:dross`) [built]: real terrain (below), permanent night (`fixed_time` 18000), normal hostile mob spawn rates.
   - Zombies spawn in full netherite armor + netherite sword. Skeletons spawn in full netherite armor and keep their bows. Nothing is enchanted (including the bow). None of this gear drops on death. Risen undead (step 6) are skipped by this rule: their gear comes only from Deathforged.
   - Slimes, creepers and spiders are removed from the spawn list. **The Cinder Wastes** have their own list: only the Colossus's stone and lava golems (step 8). **Blightwood** has no zombies, skeletons or endermen either: only rats and witches (step 11).
   - Players see the dimension named **"The Dross"** (lang key `dimension.dross.dross`).
   - **Terrain** [built] (Terrain v1, October 2026; design `tools/terrain/TERRAIN_DESIGN.md`, tuning guide `tools/terrain/README.md`, report `TERRAIN_REPORT.md`): Minecraft's noise generator, set up in data files written by `tools/terrain/worldgen.py` (every tuning number a labeled constant). A 2D height field: no caves, overhangs or floating land (the only underground spaces are Blightwood's sewers, step 11). Rolling hills, cliff steps (9 and 18) and knolls in rocky areas, Cinder mesas, and the Gravecrags' snow-capped ridged peaks (about y 230-260). Five biomes, regions about 600-670 blocks across: **Silverwood Forest** (about 42%, always round the hub), **Cinder Wastes**, **Blightwood**, **Rimefall** and **The Gravecrags** (never within about 750 blocks of the hub). (There was a sixth, the **Nether Scar**, until October 17, 2026: the user had it removed. Its land went to the biomes round it without moving any other border, and its four blocks, Scarred Netherrack, Scar Roots, Soulwick and Scar Vent, are kept as building blocks that no longer generate.) Each biome has its own ground cover, features (trees, plants, ponds, lava pools, giant mushrooms, dead trees, lichen, boulders), fog/sky/water colours, particles and sounds; ores (coal, gold nuggets, Moonsilver, Stormite) lie under every biome. New worlds only: the old flat `dross_flats` biome was removed (October 17 cleanup).
   - **Blocks** [built]: 38 terrain blocks and 3 materials (listed in "Terrain v1" below), plus the sewers' Sewer Sludge and Blight Vent (step 11).
   - **Sky, fog and light** [built] (`dimension/client/`): night fog in each biome's colour, a blue glow over the night sky, a slight blue tint on sky light, no clouds, thicker fog in Blightwood; every part switchable and self-disabling on error.
   - [built] The hub at Dross 0,0 is a safe zone (step 5).

2. **Dross portal**
   - **Frame** [built]: a custom block, `dross:dross_portal_frame`, which **can't be crafted or mined** (no recipe, no drops, unbreakable, blast-proof). For testing, it has a block item that is only available in the creative **"Dross"** tab (or `/give`); it still has no recipe, drops nothing and can't be broken in survival. Flint and steel can't light it, and normal obsidian frames stay normal purple nether portals.
   - **Frame look** [built]: an **original** texture (dark stone with electric blue cracks), no longer based on Mojang's obsidian.
   - **"The Dross is leaking out"** [built]: frame blocks give off drifting electric blue particles and a low ambient sound. This applies to every frame, including the unlit castle frame.
   - **Lighting** [built]: throwing the **Rift Key** (step 7) into the empty middle of a valid frame (along X or Z) **uses up the key** and lights the portal.
     - If that frame is already lit, the key isn't used: it pops back out, with a portal cooldown so it doesn't drift into the Dross.
     - A netherite ingot no longer lights anything.
   - **No portals inside the Dross** [built]: the Rift Key does nothing there, and lighting a nether portal (flint and steel or fire on obsidian) is blocked there. Otherwise a nether portal would be a second way out.
   - **Portal look** [built]: Minecraft's nether portal texture copied and recolored **electric blue** (still a recolor, see Parked), blue particles, and a blue in-portal screen swirl.
   - **Stays open**: once lit, the castle portal stays open permanently, for everyone.
   - **Travel** [built]:
     - Every Dross portal outside the Dross leads to the **hub at Dross 0,0** (step 5).
     - The hub's exit portal always leads to the **castle portal** (`PortalSite`), wherever the player came in.
     - No more auto-built return portals, and no saved return-portal lookup.
     - All entities can travel. Never place an entity inside blocks or above a void drop.

3. **The castle (portal site)**
   - **The castle** [built]:
     - Placed once per world, at the site location, on flattened ground (reuse the existing site-placement logic). The frame is unlit and fully unbreakable.
     - If `data/dross/structures/portal_castle.nbt` exists, that template is placed. The user builds it in creative and saves it with a structure block as `dross:portal_castle`.
     - Otherwise the **Fallen Cathedral** [built] (shrine design No. 1, the user's pick; `world/PortalCathedral`, `ShrineDesign.buildFitted`, `world/shrine/GroundFit`, `world/shrine/TreeFelling`): its 3x5 frame opening (along X) sits on the site column (see **Location**), front facing south. Its 61x87 footprint is fitted gently into the (already nearly flat) ground:
       - the footprint is levelled at the median natural height by cutting or filling a few blocks; small dips and caves just under the ground are filled (never deeper than 8 / 16 blocks); no big foundations;
       - **staircase blend** [built]: around the footprint, a column d blocks out is never more than d above or below the build level, so the ground steps at most 1 block at a time back to the natural terrain (no cliffs or walls of dirt); one column is never changed by more than 8 blocks (`MAX_RING_CHANGE`); new ground keeps each column's own top layer (grass, podzol, sand over sandstone, snow);
       - **trees** [built]: only trees that touch the footprint or a reshaped column are removed, and always whole (logs, leaves, vines, bee nests, snow on them); leaves no remaining log holds up go too, other trees are left alone. Huge mushrooms and ice spikes follow the same rule.
       - **built a step a tick** [built] (`PortalCathedral.Building`, `ShrineDesign.startFitted` / `FittedBuild`, `GroundFit.Fitting`, `TreeFelling.Felling`; the Dross hub uses it too): felling the trees (the slow part, cut into steps of at most about 40 ms, `GroundFit.STEP_MILLIS`), levelling, sealing, snow, the template (one step) and the frame check each run on their own server ticks, with exactly the same result as all at once (`world/shrine/SteppedFitGameTest`); `buildFitted` still does it all at once. Needed right away (`PortalSiteBuilder.ensurePlaced`), the rest is done at once; if the server stops after the first tree is removed, the rest is finished before the world is saved.
     - Only if the cathedral can't be built (template missing, or its frame fails the check; an ERROR is logged), the small placeholder ruined shrine (`PortalShrine`, vanilla stone bricks, 4×5 frame along X) is built instead.
     - The template must contain exactly **one** complete Dross frame with an empty opening (either direction). The code finds it and stores its bottom corner **and axis**.
     - Structure blocks save at most 48×48×48 in 1.20.1, so a bigger castle needs several pieces.
   - **Location** [built] (`world/SiteRules`, `SiteSearch`, `SiteCheck`, `PortalSitePlacer`, `SiteVillages`; all rules are labeled constants in `SiteRules`): chosen once when a new world starts and saved in `PortalSiteData`.

One that's already fighting keeps its target until it dies or becomes invalid; when a fight ends it helps allies still fighting before following. A target that is dead, dying or removed is dropped right away, even the mob whose hit raised them dying on that same hit, and any walk toward it stops at the same moment, so skeletons lower their bows instead of walking to the empty spot (`RisenTargetGoal` sets and clears every target itself and ends the fight with `endFight`; `RisenTargetGameTest` checks both headlessly). Rage Wand exception: an ally and a risen undead raged on different teams may fight (`RisenAllyGameTest` checks all of this headlessly). Whenever a risen undead damages a mob (arrows included), that mob switches its target to the risen undead that hit it, including zombies, skeletons and their variants, which normally ignore other undead. Risen drowned always fight on land, day or night. On Peaceful, Necromancy does nothing and no souls are spent. They crumble in a puff of electric blue particles after 60 seconds, or early if the owner logs out, dies or changes dimension, or if their chunk is reloaded from a save. Built in stages on branch `terrain-v1`, each checked headlessly and committed; the user play-tested it twice and their feedback is built in. The full report, every choice made and the in-game checklist are in `TERRAIN_REPORT.md`; the design now lives in The plan (steps 1, 4, 5 and 8) and the Areas table.

**The request:** replace the superflat Dross with real terrain (Twilight Forest feel, own character): rolling land, rocky cliffs and outcrops where they fit, a mountain area. Surface only (no caves, carvers or aquifers). Always night, electric blue identity: blue-tinted fog and sky, blue accents (colours from `DrossColors`). Every biome gets its own original plants, ground cover and blocks. Keep the current mob spawn rules in every biome. Tuning numbers (hill height, cliff frequency, mountain height, tree density, ore amounts...) are labeled constants.

**The user's answers:**
- **Biomes about 400-800 blocks across** (Nether Scar: smaller patches). **Small ponds only** (dark water in Silverwood, murky in Blightwood, frozen in Rimefall); no seas or rivers.
- Six biomes: **Silverwood Forest** `dross:silverwood_forest` (the main biome, dense and dark, silverwood trees with Stormvine; it surrounds the hub), **Cinder Wastes** `dross:cinder_wastes` (volcanic: basalt, magma, ash, small lava pools; future home of the Fire Necromancer), **Blightwood** `dross:blightwood` (rotten and fungal: giant decaying mushrooms, mycelium, sickly fog; future home of the Plague Necromancer), **Rimefall** `dross:rimefall` (frozen: packed ice, snow, frost-covered dead trees; future home of the Ice Necromancer), **Nether Scar** `dross:nether_scar` (patches where the Nether bleeds through: netherrack, crimson and warped fungi, soul sand), **The Gravecrags** `dross:gravecrags` (the mountain area: high rocky peaks and cliffs, peaks about y 230-260; future home of the Earth General).
- The hub (the Shattered Spire at 0,0) sits properly on the terrain: footprint levelled, edges blended like a staircase (at most 1 block per step), the 48-block safe zone still works, arrivals land correctly, never in the Gravecrags.
- **The two survivors** (never call them guards, in code, names or text): **the Blind Oracle** (skin 8, the **mentor**) and **the Ragged Seeker** (skin 3, the **student**), spawned at the hub. They walk around together, in and around the spire and out of its front gate, never more than **20 blocks outside its walls**. Exactly like the trader, they can be hit and knocked back but never die (at half health they heal and pop back to their spot), and hostile mobs ignore them. No trades.
- `/dross goto biome <name>` teleports you to the nearest example of each Dross biome (`silverwood_forest`, `cinder_wastes`, `blightwood`, `rimefall`, `nether_scar`, `gravecrags`).
- **Later (October 17, 2026): the Nether Scar biome was removed** at the user's request ("can we remove the nether scar as a biome as well"). Its land went to the biomes round it (each place gets the biome its heat and rot say; no other border moved), `/dross goto biome nether_scar` is gone, and its four blocks (Scarred Netherrack, Scar Roots, Soulwick, Scar Vent) are kept as building blocks only. The answers above are kept as a record.
- Top-down previews of a generated area (height and biome maps) in `terrain-previews/`.

**Blocks** (all original textures, drawn by `tools/terrain/`): Duskstone (the Dross's base stone), Duskstone Coal Ore, Duskstone Gold Ore (drops gold nuggets like nether gold ore), Stormite Ore (Stormite Shard: glowing blue crystal, for special arrows and the Great Mystic Bow later), Moonsilver Ore (Raw Moonsilver, Moonsilver Ingot: a pale metal for anti-undead gear later); silverwood log, wood, stripped log, stripped wood, planks, leaves, sapling; Stormvine (glowing electric blue vine on silverwood trees, decoration only); Silvermoss, Glimmer Fern, Wispbloom (Silverwood Forest); Ash, Ash Layer, Charred Log, Emberweed, Cinder Vent (Cinder Wastes); Sporeloam, Blightcap Block, Rotting Blightcap, Blightcap Stem, Gloomcap, Sporepod (Blightwood); Hoarfrost, Frostbitten Log, Frostbloom, Icicle (Rimefall); Scarred Netherrack, Scar Roots, Soulwick, Scar Vent (Nether Scar; kept as building blocks since the biome was removed on October 17, 2026); Cragstone, Storm Lichen, Crag Thistle (Gravecrags).
